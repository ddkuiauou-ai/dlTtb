# Feed browser regression

`pnpm test:browser:install` installs the Chromium revision used by the pinned test dependency. Start the development server with `pnpm dev`, then run `pnpm test:browser`. The configuration also starts the development server when no local instance exists.

`FEED_TEST_BASE_URL` overrides the browser URL. `PLAYWRIGHT_CHROMIUM_EXECUTABLE` optionally selects an already installed Chromium executable. An alternate executable is reported as that browser version, rather than the pinned Chromium revision.

The development-only `/test-feed` and `/api/test-feed` routes return 404 in production. They use synthetic posts, the actual `InfinitePostList`, `PostGrid`, and application providers. Neither route imports business queries or writes business data. Fixed card heights and independent reference metadata expose missing IDs even when those cards have disappeared from the virtual DOM. Overscan rows are permitted.

The explicit zero-margin test is a failing-design control that passes only when positive-offset rows are omitted. Corrected tests require complete viewport coverage. Geometry tolerances are CSS pixels after layout settling. Mobile viewport tests are Chromium emulation, not verification on a physical mobile device. Safari, physical-device behavior, external content/media, and business-data ingestion remain separate acceptance work.

The suite also covers fixed and mixed measured heights, actual card list/grid layouts, dynamic upper sections, append delays/errors/missing pages, duplicate-only page continuation, seed updates, generation updates, direct page URLs, detail return session markers, column changes, read filtering, modal close markers, and a delayed old-base manifest. A saved old-base navigation callback is invoked after switching feeds to verify that it cannot lock the current feed's loader. A real card cloned into the upper section with the same post ID verifies that restoration selects the active feed card. The dev fixture exposes the real cache API for IndexedDB isolation, legacy-entry, empty-hit, and storage-denial checks. Pending URL/detail restoration is interrupted with a real wheel event. Uncaught browser errors fail the test; retries are not configured.

The old-base manifest race waits up to 20 seconds for real development-server page responses and append commit. Its first final-source run exhausted the original 10-second poll immediately before a valid 120-ID commit; that failed trace remains in the evidence. Network wait time is separate from position assertions and does not certify a global two-second stabilization SLA.

Absolute position assertions against the cumulative reference allow at most 1 CSS pixel in the initial/warmed fixed-height cases: viewport widths 390/820/1440 and upper offsets 0/180/3000. Coverage checks also compare actual DOM row placement with the assigned inline transform within 1 CSS pixel. That placement check is distinct from the independent cumulative reference. Reading-anchor and current detail-return viewport alignment assertions allow at most 2 CSS pixels after settling. This is not a global 1-pixel acceptance claim for every restore or every frame.

An unmeasured prefix retains estimated heights during restoration. The final detail-return sample differed by 66 CSS pixels from a fully measured cumulative document-coordinate reference while preserving the existing 12vh + 8px viewport alignment. Assigned virtual-row placement (`root viewport top + vi.start - scrollMargin`) and that independent global-prefix reference must be reported separately. The acceptance criteria for this restore are viewport ID coverage, correct assigned row transforms, and the 2-pixel viewport alignment; the global-prefix estimate is retained as a limitation.
